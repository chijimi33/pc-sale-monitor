## 初期計測で判明した課題

2026-09-14 14:28 JSTの公開結果では巡回完了2/10店。Actionsが成功しても、全店の価格取得成功を意味しない。最新の結果は [最新索引](https://raw.githubusercontent.com/chijimi33/pc-sale-monitor/monitor-data/public/latest.json) と [検証結果](https://raw.githubusercontent.com/chijimi33/pc-sale-monitor/monitor-data/public/validation.json) を参照する。

| 対象 | 確認した課題・対応 |
|---|---|
| Yahoo! | ユーザー回答はClient ID未取得。設定待ち。履歴や現在価格を捏造せず、取得率の不足として記録 |
| Joshin / Sofmap | 403応答。取得できた商品だけ保持し、取得失敗を在庫切れにしない |
| ツクモ | ローカルでは取得できたがActionsから接続切断。原因を記録して次回再試行 |
| ビック / ヨドバシ | タイムアウトなど。ヨドバシは表示後取得も確認したがプロトコルエラーが残る |
| Amazon | 商品によって購入欄・状態・販売者同一性・送料の確認不足。ちもろぐ価格で補完しない。初回送料無料を一般送料に含めない修正済み |
| ark / 工房通販 | 一部の階層の深いセールページが未処理。入れ子のセールへの巡回とarkのBTO候補検出を追加。BTO構成の同一性は確認待ち |
| 工房チラシ | 共通版を一度解析。OCR結果と画像URLを `flyer_review.json` にまとめて確認へ渡す。掲載数量は店舗在庫へ変換しない |

共通基盤では、同一巡回内の失敗ページの重複取得を抑止し、今回未取得の前回価格を現在比較から除外した。数値境界、誤同定、履歴・再開、共通チラシ、条件付き送料を含むローカル48テストが合格。
